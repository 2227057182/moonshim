# MoonShim 项目申报书

## 项目名称

MoonShim：可编译的 MoonBit 公共 API 迁移适配器

## 项目方向与定位

开发工具 / 生态基础设施。MoonShim 面向 MoonBit 库升级中的公共接口兼容问题：读取两个版本由 `moon info` 生成的 `.mbti`，识别 API 变化，并根据维护者确认的重命名规则生成可编译的兼容包装和类型别名。

现有工具通常回答“发生了什么破坏性变化”，MoonShim 继续回答“能否安全生成兼容层，能否让旧调用方继续编译”。它不替代接口检查器，而是把检查结果推进到可执行修复。

## 三个使用场景

1. **库作者发布升级版本。** 作者把旧名保留一个迁移周期，并通过生成的 shim 让已有调用方继续编译。
2. **应用维护者升级依赖。** 开发者先获得结构化差异和可编译适配器，再集中处理真正不兼容的部分。
3. **CI 发布门禁。** 仓库对比发布前后的 `.mbti`；没有明确规则的删除或签名变化使 CI 失败，防止兼容性回退被静默合入。

## 核心功能

- 解析公开函数、方法、类型别名、结构体、枚举、Trait 和值。
- 统一参数模式、默认值、返回类型与类型体，进行分类。
- 通过 JSON 规则显式声明旧名到新名的映射。
- 为形状一致的函数生成包装，为一致的类型体生成别名。
- 生成 Markdown 人工报告和 JSON CI 报告。
- 对语义不确定、签名不一致或没有规则的删除坚决阻断。

## 原创性与工作量

项目为原创实现，不复制现有 MoonBit 项目代码。与只做兼容性分析的库相比，本项目的独立贡献是“规则约束下的代码生成 + 旧调用方编译证明”。第一版聚焦显式函数与类型重命名，范围可在赛期内完整交付，并具备继续支持迁移计划、Trait 适配和源码 codemod 的扩展空间。

## 技术方案

核心库完全使用 MoonBit，采用声明扫描、括号平衡、参数归一化和保守形状比较。生成器保留旧签名，为匿名参数赋予稳定名称，为方法恢复 `self` 接收者，并以命名参数转发可选参数。CLI 负责文件读写和退出码，不包含业务判断。

`compat_fixture` 同时保留新版 API、旧名调用方和生成结果；每次生成后由 `moon test` 验证旧代码仍能编译与运行。

## 验收与工程边界

- `moon check --deny-warn`、`moon test --deny-warn` 和 `moon fmt --check` 通过。
- GitHub Actions 重复执行端到端生成、内容稳定性检查和测试。
- 输入输出确定，不联网，不依赖大模型推理。
- Apache-2.0 许可证，README 说明安装、限制、迁移流程和回滚方式。

## 不承诺的范围

第一版不会自动推断两个函数语义等价，不会对所有破坏性变化生成猜测代码，也不会直接改写调用方源码。无法证明安全的改动必须由维护者处理。
